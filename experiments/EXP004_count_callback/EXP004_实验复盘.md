# EXP004：ROS2 C++ Subscription Callback 状态管理

## Goal
验证 Listener 跨回调累计消息数量，每收到 5 条打印一次日志。

## Environment
- Ubuntu 24.04 / WSL2
- ROS2 Jazzy
- Package: l3_r1_cpp
- Publisher: l3_talker
- Subscriber: l3_listener
- Topic: /l3/chatter
- Message: std_msgs/msg/String

## Prediction（运行前已提交）
- Publisher 约 5 Hz
- Listener 每收到 5 条打印一次
- 日志通常约 1 Hz
- 计数为 5、10、15、20……
- 消息内容为 RGBD ready

## Code
使用 std::shared_ptr<int> 保存计数状态。
Lambda 捕获共享指针，每次回调执行 ++(*count)。
count 为 5 的倍数时调用 RCLCPP_INFO。

## Result
- 修复后的 Listener 编译：PASS
- Publisher count（启动前）：0
- Subscription count（启动前）：1
- Listener 日志计数：5 至 80，每次递增 5
- 消息内容：RGBD ready
- 大多数相邻计数日志约间隔 1 秒
- count 25 到 30：约 0.369 秒，存在异常
- 原始日志：同目录 listener_*.log

## Prediction vs Result
核心计数行为符合预测。
日志间隔并非全程严格 1 秒。

## Analysis
接收回调与日志输出是两种不同的行为。
80 次累计回调可以只产生 16 行计数日志。

不能根据日志频率直接推断所有时刻的消息接收频率。

## Debug Record
此前使用 mutable Lambda 时，Jazzy rclcpp/function_traits
无法完成本次回调类型识别，导致编译失败。
改为 shared_ptr<int> 捕获后，重新编译通过。

## Conclusion
Callback 持久状态管理和每 5 条输出一次的功能验证 PASS。
单次实验不足以证明严格实时性、零丢包或长期稳定性。
