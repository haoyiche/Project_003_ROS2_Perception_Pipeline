# EXP005：ROS2 Topic Remap 故障注入与恢复

## 目标
验证 Topic 名称不匹配时的 ROS Graph 状态，
学习通过 Remap 制造、定位和修复通信故障。

## 运行前预测
- /l3_talker 和 /l3_listener 均可见
- /l3/chatter: Publisher 1 / Subscriber 0
- /l3/chatter_wrong: Publisher 0 / Subscriber 1
- 错误 Listener 不输出 Received count
- 移除 Remap 后恢复接收

## 控制变量
- 保持 Publisher、消息类型、QoS、发布频率不变
- 仅将 Listener 的 Topic 重映射到 /l3/chatter_wrong

## 实测证据
- 两个自定义节点均出现在 ros2 node list
- Listener 实际订阅 /l3/chatter_wrong
- /l3/chatter: Publisher 1 / Subscriber 0
- /l3/chatter_wrong: Publisher 0 / Subscriber 1
- listener_wrong_topic.log: 0 行
- listener_restored.log: Received count 5 至 90
- 恢复后消息内容为 RGBD ready
- 额外 /talker 节点发布 /chatter，未参与本实验

## 根因
Publisher 与 Subscriber 使用不同 Topic 名称。
端点均存在，但没有形成所需的数据传输路径。

## 修复
取消 Listener 的错误 Remap，恢复订阅 /l3/chatter。

## 结论
故障注入、Graph 定位、通信恢复均 PASS。

## 边界
本实验没有测试 QoS 不兼容或消息类型不匹配。
本实验不证明长期运行的可靠性或零丢包。
